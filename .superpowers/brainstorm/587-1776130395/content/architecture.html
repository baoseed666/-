架构方案选型

选择最适合11天黑客松的技术架构

A

🏗️ 模块化单体（推荐）

NestJS 单体，内部按模块严格分层；Vue3 SPA；PostgreSQL + Redis；独立爬虫进程

[ Vue3 H5 ]
↓ REST / SSE
[ NestJS API ]
├─ AuthModule (SMS→微信)
├─ ChallengeModule (DeepSeek/Claude)
├─ ShopModule (爬虫数据)
├─ BattleReportModule (海报生成)
└─ LBSModule (拼单匹配)
[ PostgreSQL ] [ Redis ]
[ Scraper Worker ] ← 独立进程

优势

  • 开发最快，调试最简
  • 11天内可完整交付
  • 模块边界清晰可演进

权衡

  • 单点部署，后续拆分需重构
B

🔬 微服务架构

Auth / Challenge / Scraper / Report 各自独立服务，API Gateway 聚合

[ Vue3 ]
↓
[ API Gateway ]
↙ ↓ ↓ ↘
[Auth][Challenge][Shop][Report]
各自独立数据库 + 消息队列

优势

  • 架构"好看"，评委印象加分
  • 服务可独立部署扩展

权衡

  • 11天极难完整交付
  • 调试复杂度×5
  • 黑客松杀手
C

⚡ 单体 + 爬虫独立服务

主体同A，但爬虫拆成独立微服务 + 队列，爬取时不影响主服务性能

[ Vue3 ]
↓
[ NestJS 单体 ]
↕ Bull队列
[ Scraper Service ]
多城市 / 多品类并发爬取
[ PostgreSQL ] [ Redis ]

优势

  • 爬虫不阻塞API服务
  • 队列支持重试/限速
  • 主体仍然是单体，开发快

权衡

  • 需多配置Bull+Redis队列
  • 比纯A略复杂

⭐ 推荐 A 或 C — 真实数据爬取量大选C更稳，纯速度优先选A
