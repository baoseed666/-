🎯 挑战生成 Prompt 架构（三层）

Layer 1 — System Prompt（角色定义）
你是"抠门大王"AI挑战官。目标：在用户预算内找到最极限的省钱方案， 但必须保障人身安全，不得推荐任何违法、危险、损害健康的行为。 你可以灵活替换用户活动类型，但需告知原因。输出必须是严格的JSON。
Layer 2 — Context Injection（动态注入）
注入内容：用户输入 / 城市实时店铺数据（从ShopModule取Top15相关店） / 当前时间段（午市/晚市/深夜）/ 天气 / 今日平台热门优惠关键词
Layer 3 — Output Schema（JSON强约束）
{ plans: [ { id, title, difficulty: "地狱"|"普通"|"简单",
  tasks: [ { type:"main"|"side"|"hidden", desc, tips:[], shop_hint } ],
  estimated_save: number, hp: number, mp: number } ] }

⚡ SSE 流式输出流程

POST /challenges → 立即返回 challenge_id
GET /challenges/:id/stream → SSE长连接
event: plan_start  → 前端显示"AI正在谋划..."
event: task_chunk  → 逐条任务流式渲染到面板
event: shop_matched → 匹配到店铺，卡片弹出
event: complete  → 三套方案全部生成完毕

🛡️ 安全护栏（内置于Prompt，非外部过滤）

• 绝对禁止：翻垃圾桶/拾荒、凌晨独自外出、乞讨、违法占道经营参与
• 需警示：超过22:00的推荐必须加"注意人身安全"提示
• 鼓励：拼单、团购券叠加、平台新用户首单、错峰消费、自带食材
• 灵活替换：AI可建议替换活动，但必须在tasks[0]说明原因

📊 战报生成 Prompt

输入：{ saved_amount, budget, people, city, tasks_completed, city_avg_save }
输出：{ headline（一句话战报）, rank_title（称号）, percentile（击败%用户）,
      hp_consumed, mp_used, flavor_text（游戏风格描述）}

称号体系： 消费韭菜 → 薅羊毛学徒 → 省钱老手 → 抠门高手 → 抠门大王 → 传说级穷鬼
